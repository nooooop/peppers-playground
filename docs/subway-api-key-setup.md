# 서울 지하철 도착 API — 개발계정(학습용) 인증키 발급·연동

이 앱은 서울시 **지하철 실시간 도착정보** Open API를 사용합니다.  
환경 변수 `SEOUL_OPEN_API_KEY`에 **정식 인증키**를 넣으면 `sample` 대신 실제 데이터를 조회합니다.

## 1. 공공데이터포털 가입 (개인 가능)

1. [공공데이터포털](https://www.data.go.kr/) 접속
2. **회원가입** → **개인회원**으로 가입 (사업자 등록 불필요)
3. 로그인

## 2. API 활용신청 (개발계정)

### 「6685」만 보이고 「신청하기」가 없을 때

공공데이터포털 해당 페이지에 **「활용신청 6,685」**처럼 **숫자만** 보이는 경우가 많습니다.

- 이 숫자는 **신청 번호가 아니라**, 지금까지 신청한 사람 **건수(통계)** 입니다.
- 이 데이터는 API 유형이 **LINK**(연계)인 경우가 많아, **data.go.kr에서 바로 키를 받지 않고** **서울시 쪽 사이트**에서 신청합니다.

→ 아래 **「경로 A: 서울 열린데이터」(권장)** 로 진행하세요.

---

### 경로 A: 서울 열린데이터 (권장, LINK 데이터)

1. [서울 열린데이터광장](https://data.seoul.go.kr/) 접속
2. **회원가입 / 로그인** (서울시 통합 로그인)
3. 상단 **Open API** 또는 검색에서 **「지하철 실시간 도착」** 검색  
   - 예: [지하철 실시간 도착정보 데이터셋](https://data.seoul.go.kr/dataList/datasetView.do?infId=OA-12764&serviceKind=1&srvType=A)
4. **인증키 신청** / **활용 신청** / **Open API 신청** 버튼 클릭 (화면 문구는 시기마다 다를 수 있음)
5. **개발·학습용** / **개인** 목적으로 신청 (하루 약 **1,000건** 수준 안내가 흔함)
6. 승인 후 **마이페이지 → 인증키 관리**에서 키 복사  
   - `swopenapi.seoul.go.kr` 주소에 넣는 **인증키**를 복사합니다.

**T Data 서울교통**([t-data.seoul.go.kr](https://t-data.seoul.go.kr/userguide/guideopenapi.do))에서 같은 교통 Open API를 안내하는 경우도 있습니다. 둘 중 한 곳에서 발급된 서울 Open API 키를 쓰면 됩니다.

---

### 경로 B: 공공데이터포털 (REST·직접 신청 가능한 경우)

페이지에 **「활용신청」 버튼**이 **있을 때만** 이 경로를 사용합니다.

1. [서울특별시_지하철 실시간 도착정보(일괄)](https://www.data.go.kr/data/15125683/openapi.do)
2. **활용신청** → **개발계정**
3. [마이페이지 → 개발계정](https://www.data.go.kr/iim/api/selectDevAcountRequestConfirm.do)에서 **일반 인증키(디코딩)** 복사

LINK만 있고 버튼이 없으면 **경로 A**로 가면 됩니다.

### 인증키 확인 (공통)

- 키는 `SEOUL_OPEN_API_KEY`에 **공백 없이** 붙여넣기
- 승인 직후 **1~2시간** 뒤에야 동작하는 경우 있음
- 이 앱 URL 형식: `http://swopenapi.seoul.go.kr/api/subway/{인증키}/json/...`

## 3. 로컬 환경 변수 설정

프로젝트 루트에 `.env.local` 파일 생성 (Git에 올라가지 않음):

```env
SEOUL_OPEN_API_KEY=여기에_복사한_인증키
```

저장 후 **개발 서버 재시작**:

```bash
npm run dev
```

### 키 동작 확인

```bash
npm run check:subway-key
```

`INFO-000` / 도착 데이터가 보이면 성공입니다.

브라우저에서 앱 **지하철** 탭 → 역 추가 후, 상단에 **「정식 인증키 사용 중」** 이 보이면 연동 완료입니다.

## 4. 배포 환경(이미 배포된 사이트) 설정

`.env.local`은 **로컬 전용**입니다. Vercel·Netlify 등 호스팅에는 **대시보드 환경 변수**로 넣어야 합니다.

| 플랫폼 | 설정 위치 |
|--------|-----------|
| Vercel | Project → Settings → Environment Variables |
| Netlify | Site → Environment variables |
| 기타 | 해당 서비스의 Secrets / Env 메뉴 |

추가할 변수:

| 이름 | 값 |
|------|-----|
| `SEOUL_OPEN_API_KEY` | 발급받은 인증키 (공백 없이) |

**Production** 환경에 추가한 뒤 **재배포(Redeploy)** 해야 반영됩니다.

### 배포 후 확인

배포 URL에서 지하철 탭을 연 뒤, 샘플 안내 문구가 사라지고 도착 정보가 표시되는지 확인합니다.  
또는 (로그인 없이) `https://배포주소/api/subway/config` 를 열어 `"mode":"development"` 인지 확인합니다.

## 5. 자주 나는 문제

| 증상 | 해결 |
|------|------|
| 여전히 「샘플 키」 안내 | 서버 재시작·재배포, 변수 이름 오타 `SEOUL_OPEN_API_KEY` 확인 |
| `ERROR-300` / 인증 오류 | 키 복사 시 앞뒤 공백 제거, 승인 후 1~2시간 대기 |
| `INFO-200` 등 데이터 없음 | 역명 정확히 입력(예: `강남`, `홍대입구`), 심야·운행 종료 시간대 확인 |
| 하루 한도 초과 | 개발계정 1,000건/일 초과 → 이용 시간 줄이거나 운영계정 신청 검토 |

## 6. 트래픽 참고 (이 앱 기준)

- 즐겨찾기 5역 × 10초 갱신 × **화면이 보일 때만** 호출
- 1회 갱신 ≈ API **5건** (역마다 1건)
- 통근 시 약 30~40분 화면 사용 → 개발계정 **1,000건/일** 안에서 사용 가능한 경우가 많음
